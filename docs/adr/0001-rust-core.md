# ADR-0001: Rust как язык ядра

**Статус:** Предложено
**Дата:** 2026-07-12
**Нужно до:** Фазы 1 (первый код)

## Контекст

У проекта две цели: практический инструмент и учебный полигон — автор целенаправленно изучает Rust, и слой валидации выбран основным носителем этого обучения (математика Безье как программа курса). Одновременно вся ключевая экосистема рендера — resvg, usvg, svgtypes — нативно живёт в Rust, а геометрические проверки чувствительны к производительности (флэттенизация и sweep по тысячам сегментов на каждый раунд петли).

## Решение

Ядро — Rust workspace. Все крейты из ARCHITECTURE.md §6 пишутся на Rust; никаких биндингов к рендеру — resvg подключается как обычная зависимость.

## Рассмотренные альтернативы

**Python.** Быстрее первый результат, богаче простор для экспериментов с промптами. Отклонён: рендер через subprocess или FFI, геометрия либо медленная, либо тянет numpy-стек, и главное — не отвечает учебной цели, которая заявлена равноправной.

**TypeScript.** Родная экосистема MCP, рекомендация большинства MCP-гайдов. Отклонён для ядра: геометрия и парсинг путей — не сильная сторона экосистемы, resvg снова за FFI. Остаётся кандидатом для тонкого MCP-слоя (см. ARCHITECTURE.md §9 — открытый вопрос Фазы 5).

## Последствия

Становится проще: единый тулчейн от валидации до рендера, честная скорость геометрии, property-тесты через proptest. Становится сложнее: старт медленнее, чем на Python, — принято осознанно, потому что «медленный старт» здесь и есть учебный процесс; риск увязнуть в борьбе с borrow checker вместо математики смягчается порядком фаз (сначала чистые функции над простыми типами, ownership-сложность приходит позже, в оркестраторе). Пересмотреть: не планируется; решение фундаментальное.
